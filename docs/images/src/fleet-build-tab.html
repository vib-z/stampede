build-steps-plan
⏺ Steps 0 to 5 are written, the report is in, and the lead has been pinged. They follow
  contract v2.3: just-do-it is the default mode, gated is for big or risky jobs, and one-agent
  jobs take the solo path in either mode. Step 3 also has the section 10 update: it checks
  whether a role's tool is installed and takes the row's fallback role when it isn't.

  What each step does:
  - 0 triage: picks the mode, size, kind, steps, gates and remote. It asks at most one question
    up front, and only when the job can't go ahead without the answer. For every other open
    question it writes down the choice it will make, so the owner can correct it later.
  - 1 collect: gathers the owner's dump, in one message or many, and offers a brainstorming
    skill (credited to its open-source source). It agrees the goal with the owner.
  - 2 plan: writes the plain plan.md in the agent's own plan mode: the goal, tasks marked clear
    or unclear, and questions.
  - 3 roles: fills the roles.md table from the roles list and one domain index. It picks each
    role's agent from the optional priority list, else what is installed.
  - 4 orchestrate: reads one pattern as a seed and writes fleet-plan.md with one plain card per
    pane. The lead is named lead-<slug> in tab lead, to match how stampede launch starts it.
  - 5 review-app: uses only the review app's commands, handles each line it prints, never
    writes the approval itself, and hands over to stampede launch <job dir>.
