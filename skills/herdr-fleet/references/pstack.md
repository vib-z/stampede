# pstack inside a fleet

pstack is optional. The Claude Code plugin `pstack@pstack-claude` ([michael-denyer/pstack-claude](https://github.com/michael-denyer/pstack-claude), MIT, these rules checked against 0.9.102 at commit `356c6e0`; commands `/pstack:...`, entry `/pstack:poteto-mode`) makes a good lead: data shape first, a contract commit, a todo list with a reason for each skip, proof on the real surface. A lead is a normal Claude Code session, so it loads pstack when pstack is installed. Its playbooks assume one Claude session with built-in subagents, so in a fleet these rules win wherever pstack says otherwise. Without pstack, nothing here applies and nothing changes.

0. **Coding jobs only.** The lead uses pstack's playbooks for coding work (features, fixes, refactors, reviews) and ignores them for non-coding jobs (research, writing, ops).
1. **Fan-out runs as panes.** Every pstack step that spawns agents (how explorers, architect and arena runners, design panels, interrogate, swarm, comment-sicko, thermos reviewers) runs as a Herdr pane on another model, or is skipped with a one-line reason in `todo.md`. Never as a hidden built-in Agent or Task subagent ([Panes, not built-in subagents](../SKILL.md#panes-not-built-in-subagents)).
2. **The fleet model table wins.** Pick each pane's app, model and effort from the table in [SKILL.md](../SKILL.md#pick-the-agent-and-model), not pstack's role models (`sonnet` for feature work, `opus`, `fable`) or a `pstack-models.md` sheet.
3. **Herdr ownership wins.** The Feature playbook's "own worktree per delegate" and "commit liberally" give way to [collaboration.md](collaboration.md): only the lead commits to shared branches and in a shared worktree; a worker in a worktree of its own commits only to its branch.
4. **The architect sketch is the contract commit.** pstack architect's sketch (types, stubs with `not implemented` bodies, one acceptance test that fails) is the lead's item 3 contract. Commit it once, before any worker starts.
5. **The todo list is a file.** Keep pstack's todo list as `todo.md` in the job folder, not in the task tools. It survives a restart and `reopen.sh`, the owner and any bot that started the job can read it, and it needs no setup. Do not set `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` for it: that changes every lead's start and keeps the list inside one session.
